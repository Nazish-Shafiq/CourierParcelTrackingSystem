# Courier Parcel Tracking System API

## Stack
- ASP.NET Core 8 Web API
- Entity Framework Core 8 (Database-First)
- SQL Server
- Swagger / OpenAPI

## Implemented endpoints

| Method | Endpoint | Description |
|---|---|---|
| GET | `/api/users` | List active, non-deleted users with role names |
| GET | `/api/users/{id}` | Get one active, non-deleted user |
| GET | `/api/customers` | List active, non-deleted customers |
| GET | `/api/customers/{id}` | Get one active, non-deleted customer |
| GET | `/api/hubs` | List active, non-deleted hubs |
| GET | `/api/hubs/{id}` | Get one active, non-deleted hub |
| GET | `/api/parcel-statuses` | List active, non-deleted statuses |
| GET | `/api/parcels` | List active, non-deleted parcels |
| GET | `/api/parcels/{id}` | Get parcel details |
| POST | `/api/parcels` | Create a parcel |

## Run
1. Open `CourierParcelTrackingSystem.API.sln` in Visual Studio 2022.
2. Check `appsettings.json` and set `ConnectionStrings:DefaultConnection` to your SQL Server instance.
3. Ensure the target database already exists and matches the scaffolded entities.
4. Run:
   ```powershell
   dotnet restore
   dotnet build
   dotnet run
   ```
5. Open the Swagger URL printed in the terminal, usually `https://localhost:<port>/swagger`.

## Create parcel request example

Use an existing active customer ID and active parcel status ID. `routeId` is optional.

```json
{
  "senderCustomerId": 1,
  "routeId": 1,
  "currentStatusId": 1,
  "expectedDeliveryDate": "2026-12-01T12:00:00Z",
  "totalWeightKg": 2.5,
  "declaredValue": 1500.00,
  "specialInstructions": "Handle with care"
}
```

## Notes
- Read endpoints exclude records where `IsActive = 0` or `IsDeleted = 1`.
- User responses never expose `PasswordHash`.
- Parcel creation validates sender, optional route, and current status before inserting.
- Tracking numbers are generated by the API.
- No migrations are added and no database schema changes are made.
- The project uses the existing scaffolded database entities. In particular, the `Customer` entity in the supplied backend does not expose a `Country` property, so the customer DTO does not assume one.
- The API has not been runtime-tested against the user's local SQL Server from this build environment. Run the build and test instructions above in Visual Studio to verify local connectivity and schema compatibility.
